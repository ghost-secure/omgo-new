# Проверочные коды

Страница: **`/manager/mant_code/`** (`catalog.php` = `gen/t_code.php`). Грид — DynBlock `t_code/base`. Столбцы собираются из `tblfields` в `config.php`, чтобы у автора и активатора был свой вывод.

Легаси: кнопка `WF::Button` (`id=codes`, `action=WF_CODEPULL`) открывала `project/phpfiles/wf/codes.php`. Форма уходила в `action.php` с `table=t_events`. Пул писал `aftersave/t_events.php`. Строка кода — `Object\Code\Code::makeCode` (тот же метод вызывает `aftersave/t_code.php` у одной новой записи).

## Грид

Создание записи остаётся. Правки нет: `meta.actions.edit = false`, карандаша в строке нет.

Удаление есть только у свободного кода. Активированный — тот, у которого заполнен `date_activate` (в легаси свободный код ищется как `date_activate IS NULL`) или `user_activate` больше нуля. Кнопка скрыта условием `row_actions.delete_if`. Тот же запрет в `TCodeHook::beforeDelete`: запрос удаления активированного кода не проходит.

В панели фильтров два чекбокса (`config.filter_fields`, тип `flag`): «Только неактивированные» и «Только активированные». Условие то же (`CodeService::idleSql` / `activatedSql`) и уходит в `filterColumnExpressions` страницы. Снятый чекбокс список не режет. Оба включённых вместе дают пустой список: код не может быть и свободным, и активированным.

В колонках «автор записи» (`author_add`) и «кто активировал» (`user_activate`) показывается ФИО из `t_users`: фамилия, имя, отчество (`varc_surname`, `varc_name`, `varc_patron`). Пустая ссылка — прочерк. Подзапрос задаёт `gen/t_code.php` (`CodeService::userFioSelect`). В Excel эти две колонки выгружаются той же строкой (`export_formatter`).

`user_activate` — это `t_users.cat` учётки, которая потратила код (легаси пишет туда `$sql->uid`). У лабораторий в профиле пустая фамилия, а в имени — название лаборатории (`lab-1` «Лаборатория эпигенетики», `lab-2` «Лаборатория 62-й больницы», `lab-3` «Лаборатория СПб»). В ячейке тогда это название, не ФИО человека. У врачей в тех же колонках фамилия и имя.

## Форма

`project/phpfiles/flow/codes.php`, белый список `project/config/admin_flow.php`.

Радио типа анализа (как в легаси, не весь справочник `t_analiztype`):

| id | Подпись |
|----|---------|
| 1 | HRD (рак яичников) |
| 3 | AKT (рак молочной железы) |
| 6 | BRCA (рак молочной железы, рак поджелудочной железы, рак яичников) |
| 8 | HRR (рак простаты) |
| 7 | PTEN |

По умолчанию выбран HRD. Количество — число от 1 до 500, в поле сразу 10.

«Создать коды» → `POST /jsapi/admin/code-pool` (подпись флоу + CSRF). Успех: тост «Создано кодов: N», модалка закрывается, грид перечитывается.

Строка в `t_events` не создаётся: в легаси она была только транспортом до `aftersave`.

## Генератор

`Services\CodeService::makeCode` — как `Code::makeCode`:

1. `t_analiztype.varc_name` по `cat` типа.
2. Оставить только латинские буквы (`ИГХ PTEN` → `PTEN`, `BRCA` → `BRCA`).
3. Первые 3 буквы + `-` + 4 случайных символа + `-` + ещё 4. Алфавит — `Helpers\Crypt::generateRandomString` (цифры и латиница обоих регистров).

Примеры из базы: `HRD-…`, `AKT-…`, `BRC-…`, `PTE-…`, `HRR-…`.

`generatePool` пишет N строк `t_code` (`view_analiz` + `varc_code`) одной транзакцией. Перед вставкой код проверяется на совпадение с уже существующим `varc_code` (до 8 попыток). `author_add` и `created_add` ставит ядро при INSERT.

`Project\FormHooks\TCodeHook::beforeSave` — для новой строки с выбранным типом и пустым `varc_code` подставляет тот же генератор (форма «Добавить запись»). Если код уже задан, хук его не меняет. Пул передаёт код сам, хук второй раз не генерирует.

## История логики

### 2026-10-11 — чекбоксы активации в фильтрах

- **Тип:** новая логика
- **Было:** отобрать свободные или активированные коды в панели фильтров нельзя
- **Стало:** чекбоксы «Только неактивированные» и «Только активированные», то же правило, что у удаления

### 2026-10-11 — грид кодов: без правки, ФИО, удаление только свободных

- **Тип:** новая логика
- **Было:** в строке были правка и удаление любой записи; автор и активатор показывались числом `tblusers` / `t_users.cat`
- **Стало:** правки нет; удалить можно только неактивированный код; в этих двух колонках ФИО из `t_users`

### 2026-10-11 — пул кодов в кабинете

- **Тип:** новая логика
- **Было:** страница `t_code/base` без сценария; пул жил только в легаси (`wf/codes.php` + `aftersave/t_events.php`)
- **Стало:** кнопка в тулбаре, модалка типа и количества, `CodeService` пишет пул в `t_code`
