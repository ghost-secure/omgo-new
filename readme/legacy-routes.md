# Легаси-адреса (`logic/index.php`)

Эталон: `omgo-lu/project/logic/index.php`. Адрес сверяется с шаблоном. Совпало — открывается страница каталога, кусок URL уходит параметром маршрута (`RouteMatch` attributes). Иерархия каталога эти хвосты не резолвит: `1171` и GUID не являются `mapurl`.

Стратегия: `Strategy\LegacyUrlStrategy` (приоритет 250, после `HomepageStrategy` 300). Корень `/` — отдельно в `HomepageStrategy`.

## Вход в кабинет

Публичной витрины нет. После входа:

| Адрес | Куда |
|-------|------|
| `/` | 302 на `/manager/mant_pacient/` |
| `/manager/` | 302 на `/manager/mant_pacient/` |

Список пациентов — страница `Helpers\Page::PACIENT_LIST`, `mapurl = mant_pacient`, php `gen/t_pacient.php`. Гость до стратегии не доходит: `AuthHook` (`auth.gate=all`) уводит на `/login`.

Номера страниц (`catalog.id`) лежат в `Helpers\Page`, не в стратегиях. `Core\Page\Page` — объект маршрута, не этот список.

## Паспорт врача

`/manager/doctor/{cat}/` — числовой `t_users.cat` (в легаси переменная называлась `doctor_guid`).

Страница `Helpers\Page::DOCTOR`, `mapurl = doctor`, php `web/doctor-passport.php`, шаблон `light.php`. `catalog.status = 0`: в меню пункт не попадает, голый `/manager/doctor/` иерархия не открывает. Стратегия отдаёт страницу только если id есть в `t_users` и это `Page::DOCTOR`. Параметр: `doctor_id`.

Страница — два DynBlock:

| Блок | Легаси | Шаблон | Фильтр |
|------|--------|--------|--------|
| Карточка | `tbldynelements` 58 | `t_users/doctor-card` (свой `template.php`, без `meta.ui`) | `t_users.cat = doctor_id` |
| Список пациентов | `tbldynelements` 54 | `t_analysis/doctor-patients` (`admin-table`) | `t_analysis.user_doctor = doctor_id` |

Карточка не на `admin-table`: на странице один грид. Два `admin-table` делят `id="filters-form"`, и фильтр списка читал бы форму карточки. В карточке ФИО, лаборатория, медучреждение, регион.

Список: столбцы шапки блока 54 (код, дубль в другой лаборатории, ФИО со ссылкой на `/manager/passport/{varc_guid}/`, даты, диагноз, регионы, анализ, статусы, просрочка `cnt_late`). Пустые «Статус мутации» и «Статус HRD» — прочерк. Создание, правка и удаление строк выключены. Панель фильтров по всем полям `t_analysis` выключена (`filter => false`, в том числе у скрытых колонок): иначе селекты справочников раздувают страницу. Запрос столбцов общий с основным списком: `AnalysisService::analysisGridQuery()`. На паспорте к нему добавляется `user_doctor`. Кнопки маршрута заявки и раскраска строки из легаси на этой странице нет.

Тот же грид — `/manager/mant_pacient/`, шаблон `t_analysis/list`. Роль режет строки и показывает кнопку «Добавить пациента». См. [patients.md](patients.md).

Ссылка «пациенты» в гриде врачей ведёт сюда. См. [doctors.md](doctors.md).

## Форма пациента

`/manager/pacient/` — новая заявка, GUID нет. `/manager/pacient/{guid}/` — заявка уже создана, `analysis_guid` = `t_analysis.varc_guid`.

Страница `Helpers\Page::PACIENT`, `mapurl = pacient`, php `form/pacient.php`, шаблон `light.php`. `catalog.status = 0`: в меню пункт не попадает, голый адрес без стратегии иерархия не открывает. На адресе с GUID — карточка черновика. См. [patients.md](patients.md).

## PDF заключения

`/pdf/{guid}/` — `t_analysis.varc_guid`. Это не страница каталога: `matchPdf()` строку не читает и шаблон не подключает. Тело — `form/pdf.php`. Параметр: `analysis_guid`.

Шаблон, роли и внешняя печать — [pdf.md](pdf.md).

## Паспорт анализа

`/manager/passport/{guid}/` — `t_analysis.varc_guid`. Страница `Helpers\Page::PASSPORT`, `mapurl = passport`, php `web/passport.php`, шаблон `light.php`. `catalog.status = 0`. Параметр: `passport_guid`. Отдаёт `matchPassport()`.

Кто открывает заявку — `AnalysisService::denyReason`: врач только свою (`user_doctor`), спонсор и спонсор-аудит — нет. То же правило у PDF.

Карточка — DynBlock `t_analysis/passport`. Шапка (ФИО, факты, «Действия», «Операции») всегда видна. Ниже кнопки вкладок `UC\TabSet`: «Общие сведения», «Материалы», «Анализ», «История статуса». «Анализ MLPA» есть только у блока 49, если у заявки есть дочерняя строка `cnt_analysislinked`. Открыта одна вкладка, первая по умолчанию. «Информация о пациенте», «Информация о диагнозе» и «Комментарий» — заголовки внутри «Общих сведений», не кнопки. Галочка на «Материалы», если есть кровь или гистология, и на «Анализ», если заполнен результат. AKT и AKT BRCA — блок легаси 61 (материалы тремя маркировками, без MLPA). Остальные типы — блок 49. Строка «свойство: значение» — `UC\PropLine`: подпись `font-bold text-blue`, пустое значение — прочерк. Заголовок и его строки — `UC\PropGroup` (`gap-sm`). Между группами карточка держит `gap-md`. Код пациента скрыт, когда первая роль в `roles_map` — врач. Действия — кнопки воркфлоу. Операции — ссылки и, только на паспорте, «статус пациента», «изменить лаб-ю», «изменить ФИО или дату рождения». Кто их видит — [analysis-workflow.md](analysis-workflow.md). Кнопки «Удалить заявку» у суперадмина ещё нет.

## Намечено: GUID анализа

`match()` этот адрес не берёт. GUID — `t_analysis.varc_guid`.

| URL | Страница | php | Параметр | Кто заполняет |
|-----|----------|-----|----------|----------------|
| `/manager/analysis/{guid}/` | `Page::ANALYSIS` | `form/analysis.php` | `analysis_guid` | лаборатория, форма анализа |

Страница в каталоге со `status = 0`. Карта в коде: `LegacyUrlStrategy::plannedGuidRoutes()`.
