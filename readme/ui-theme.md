# Оформление кабинета (светлая тема)

Цель: приблизить светлую тему к легаси OMGO. Темную не трогаем, пока нет отдельного пункта.

## Что с test, что нет

Ядро (`core/assets/`: `config-default.css`, `config.css`, `components.css`, плагины) уже то же, что на test. Отдельно с test **не копировали** магазин и шрифт Geologica.

Единственный проектный CSS админки на test — `project/overrides/assets/config-light.css`. На OMGO его не было: `core.js` грузит файл и при 404 молча идёт дальше. Из‑за этого в светлой теме не было чёрных тултипов.

Причина в ядре: `--tooltip-bg` задан в `config.css` на **`.light-theme`**, а `<html>` носит класс **`theme-light`**. Токен не применяется. На test это закрыто `:root` / оверрайдом. На OMGO — `html.theme-light` в своём `config-light.css` (не чужой индиго `#3834DA`).

## Мнемоники цвета

Справочники статуса и типа анализа хранят не hex, а имя токена: `green`, `blue`, `yellow`, `red`, `lgrey`, `purple`, `deepgreen`, `pink`.

В светлой теме эти токены заданы в `config-light.css`. Сплошной цвет — класс `bg-green` и `var(--color-green)`. Фон строки — `var(--color-bg-green)`. Другого зелёного в разметке списка нет: ни фона, ни текста, ни границы. Как список это применяет: [patients.md](patients.md).

Список пациентов читает не короткий блок `--blue` / `--green` / `--bgblue` из `lu-original.css` (там другие hex), а `--color-*` и `--color-bg-*` из `uikit.css`, который `lu-original.css` подключает. Исключение: `.bg-pink` читает `--pink` из блока variables `lu-original.css`. `--color-lgrey` ядра (границы, `#d5d5d5`) не подменяем легаси `#b9bac7`: бледный фон статуса — отдельный `--color-bg-lgrey`.
