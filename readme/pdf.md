# Заключение PDF

Адрес `/pdf/{guid}/`, GUID — `t_analysis.varc_guid`. Страница `Helpers\Page::PDF` (`catalog.id` 69), php `project/phpfiles/form/pdf.php`. Шаблон страницы — пустой `_empty.htm`: в ответ не попадает кабинет `light.php`.

Легаси: `project/phpfiles/form/pdf.php` и `Object\PDF\PDF`.

## Кто открывает

Гейт пускает на адрес только вошедшего. Дальше `ConclusionAccess`, как в легаси:

| Кто | Доступ |
|-----|--------|
| Врач | только заявка, где `t_analysis.user_doctor` = id учётки |
| Спонсор и спонсор-аудит | нет |
| Лаборатория, администратор, суперадмин | да |

Чужая заявка и спонсор получают текст «Нет доступа для вашей учетной записи.»

## Какой шаблон

Роль шаблон не выбирает. Номер строки `tbldynelements` зависит от `t_analysis.view_test`:

| Тип | Блок | Имя в таблице |
|-----|------|----------------|
| AKT, AKT+BRCA | 63 | Заключение AKT |
| MLPA | 65 | Заключение MLPA |
| BRCA | 71 | Заключение BRCA |
| HRR | 76 | Заключение HRR |
| PTEN | 77 | Заключение PTEN |
| остальные (HRD, NGS) | 57 | Заключение |

Берутся `pHeader`, `pBody`, `pFooter`. Разметка легаси: `[=поле=]`, `[=поле=val=]`, `[=поле=nl2br=]`, `filled::`, `{if ?=}`, `{{ if }}` / `{{ elseif }}` / `{{ endif }}`, `{{ materials }}`, `{{ expressionprotein }}`, `[N_ID]`, `{param=rootpage}`.

Строка для подстановки — заявка с пациентом, врачом, типом, лабораторией и методикой лаборатории (легаси preset `pacientdata`). `view_*` и `multiselect_*` подписываются через `tblfields.table_ext` / `column_ext`. Даты `date_*` и `datetext_*` выводятся как `d.m.Y`.

`{{ materials }}`: у MLPA фиксированная кровь; иначе отмеченные материалы и их маркировка. `{{ expressionprotein }}` — две готовые фразы ИГХ PTEN по `varc_result`.

После сборки HTML сжимается так же, как `PDF::clearHTML`: переводы строк в пробел, пробелы вокруг тегов снимаются.

## Печать

Сборка HTML и сервис печати — разные классы.

1. После проверки доступа пишется одноразовый токен в `runtime/pdf-tokens/`. В файле GUID заявки.
2. `HtmlToPdfConverter` (сейчас `RemoteHtmlToPdf`) делает POST на адрес из окружения. В теле: `url`, `format`, `orientation`, `token`.
3. `url` — полный адрес из `APP_BASE_URL`: `/pdf/{guid}/?create=1&temp=...`. У сервиса печати нет сессии, гейт этот запрос пропускает. Токен сверяется с GUID и удаляется. В ответ уходит HTML.
4. Байты PDF отдаются пользователю как `application/pdf`.

`PRINTPDF_REMOTE=0` выключает шаги 1–4. После той же проверки доступа ссылка `/pdf/{guid}/` сразу отдаёт HTML из пункта 3, сервис не вызывается. Так смотрятся заключения локально: имя `omgo` снаружи не открывается. На проде `PRINTPDF_REMOTE=1` (это и значение по умолчанию, если переменной нет).

Локально `APP_BASE_URL` — `http://omgo`. Вызов сервиса тоже идёт по http (`PRINTPDF_URL`), сертификат код не проверяет. Сервис печати стоит снаружи и сам открывает переданный `url`. На стенде в этот адрес подставляется публичный хост, в легаси это `https://dev.oncogenetic.org`.

Пустой ответ или обрыв связи: текст «Время ожидания истекло, мы уже занимаемся решением проблемы.» Если заданы `PRINTPDF_ALERT_URL` и `PRINTPDF_ALERT_TOKEN`, уходит POST с `project` и `message`.

Параметры в `.env`, читает `project/config/integration.php` → `printpdf`:

| Переменная | Смысл |
|------------|--------|
| `PRINTPDF_URL` | адрес сервиса |
| `PRINTPDF_TOKEN` | поле `token` запроса, бывший `apikey` |
| `PRINTPDF_TIMEOUT` | секунды, по умолчанию 40 |
| `PRINTPDF_FORMAT` | по умолчанию `A4` |
| `PRINTPDF_ORIENTATION` | по умолчанию `P` |
| `PRINTPDF_ALERT_URL` | куда слать сигнал о сбое, можно пустым |
| `PRINTPDF_ALERT_TOKEN` | заголовок Authorization сигнала |
| `PRINTPDF_ALERT_PROJECT` | поле `project` сигнала |
| `PRINTPDF_ALERT_MESSAGE` | текст сигнала |
| `PRINTPDF_REMOTE` | `0` — ссылка отдаёт HTML, сервис не вызывается. `1` или пусто — PDF через сервис |

Другая реализация печати подменяется через `HtmlToPdfConverter` в `project/config/services.php`.
