# Отчёты Excel по заявкам

Список `/manager/mant_pacient/` не собирает Excel в браузере. Крон заранее пишет файлы, кнопка «Отчет» их скачивает. Легаси: `gen/t_pacient.php` (дропдаун) и `omgo-dev/project/cron/reglament/report-alltest-new.php`.

На гриде `t_analysis/list` скрыты «Настроить таблицу» и «Выгрузить в Excel» (`toolbar_settings` и `toolbar_excel` в конфиге шаблона). Остальные гриды эти кнопки оставляют, в том числе список на паспорте врача. У врача на телефоне тулбара нет: карточки `t_analysis/doctor-mobile`.

## Кнопка

Слева в тулбаре, перед «Добавить пациента». Подпись «Отчет». В меню две обычные ссылки, не кнопки: меню по ширине текста и страницу вбок не растягивает.

| Пункт | Адрес | Файл |
|-------|--------|------|
| До 1 января 2026 | `/report/pacient/` | `before-alltest-{ключ}.xlsx` |
| После 1 января 2026 | `/report/pacient/?target=new` | самый новый `alltest-{ключ}-ГГГГММДД.xlsx` |

Граница — `2026-01-01 00:00:00` по `t_analysis.created_add`. Это дата генератора, который переносили. В старом кабинете на кнопке было «1 октября 2025»: тот текст относился к прежним файлам `allpacient-`.

Врач кнопку не видит. Лаборатория, спонсор, спонсор-аудит, администратор и суперадмин (`tblusers.role = 1`) видят. Врач кнопку не снимает: учётка лаборатории, у которой есть и роль врача, кнопку видит.

Гость до адреса не доходит (`auth.gate=all`). Файла ещё нет — ответ `no data`.

## Какой файл у роли

Поздняя роль переписывает ключ, как `phpfiles/report/pacient.php` в легаси. Врач ключ не задаёт.

| Роль | Ключ | Подпись скачивания | Столбцы |
|------|------|--------------------|---------|
| Администратор или суперадмин | `lab` | Отчет лаборатории | полный набор |
| Лаборатория, у лаборатории `t_lab.stat_exportallpacient` не 0 | `lab` | Отчет лаборатории | полный набор, все лаборатории |
| Лаборатория, флаг 0 | `lab` + id лаборатории профиля | Отчет лаборатории | полный набор, только `view_lab` этой лаборатории |
| Спонсор | `sponsor` | Отчет спонсора | без ФИО пациента |
| Спонсор-аудит | `auditor` | Отчет DX manager | без GUID, кода, ФИО, даты рождения, проверочного кода, согласия, сканов гистологии и маркировок; длинные тексты до 100 символов |

Пример: спонсор, который ещё и администратор, получает файл спонсора. Лаборатория с флагом 0 и id 8 получает `lab8`.

## Крон

```
php project/scripts/cron/report-alltest.php
```

Только CLI. Пишет в `runtime/cache/reports/`. Журнал запуска — `runtime/logs/report.log`.

На каждый ключ (`sponsor`, `auditor`, `lab` и `lab{id}` для лабораторий с флагом 0):

- архив до 1 января 2026 — один раз, если файла ещё нет;
- актуальный срез с этой даты — каждый запуск, имя с сегодняшней датой;
- старые актуальные файлы этого ключа свыше 30 штук удаляются.

Страница выборки — 2000 строк. Пустые ячейки в листе — прочерк. Шапка листа: «Отчет по всем пациентам на дату …».

`created_add` заявки и события (`t_events`) — DATETIME. Поля `date_*` — unix. ФИО пользователя — фамилия, имя и отчество, как в списке заявок. Ссылка на файл и сканы собирается от `APP_BASE_URL`.

Столбцы и форматы ячеек — `Services\Report\AnalysisReportColumns`. Выборка — `AnalysisReportQuery`. Пути и роль — `AnalysisReportFiles`. Сборка листа — `AnalysisReportExporter`.
