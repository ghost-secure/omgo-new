# Список пациентов

Страница `/manager/mant_pacient/` (вход `/` и `/manager/`). Это один грид заявок: строка — анализ `t_analysis`, рядом данные пациента `t_pacient`. Легаси собирал тот же список в `gen/t_pacient.php` через пресет `pacientdata` (`omgo-lu/project/logic/custompatterns.php`).

Интерфейс: `project/UC/dynblock/t_analysis/list`. Запрос: `AnalysisService::analysisGridQuery()`. Роли, черновик, отчёты и кнопка «Добавить пациента» сюда ещё не перенесены.

Паспорт врача `/manager/doctor/{id}/` берёт тот же SQL, но шаблон `t_analysis/doctor-patients` без этой раскраски и без этих фильтров.

## Подсветка строки и легенда

Цвет статуса лежит в `t_analiz_status.varc_color`. Это мнемоника (`green`, `blue`, `yellow`, `red`, `lgrey`), не hex и не CSS-имя цвета.

Фон строки: `var(--color-bg-{мнемоника})`. Легенда над таблицей — все статусы, у которых мнемоника есть в палитре фона. Пустая мнемоника (сейчас статус «Материал непригоден. Будет выполнен NGS.») строку не красит и в легенду не попадает.

Образец легенды красит класс `bg-{мнемоника}` сплошным цветом (`bg-green` → `--color-green`). Ячейки, включая закреплённые, берут бледный фон из `--row-tone` на `<tr>`. У `lgrey` этот фон почти белый (`--color-bg-lgrey`), поэтому такие строки выглядят незакрашенными — так же, как в легаси.

## Бейдж типа анализа

Колонка «Анализ» — название типа внутри скруглённого прямоугольника. Фон бейджа — класс `bg-{мнемоника}` из `t_analiztype.varc_color` (`bg-deepgreen`, `bg-pink`). `pink` читает `--pink`, остальные — `--color-{мнемоника}`. Текст бейджа: `var(--color-white)`. Границы у бейджа нет.

Мнемоники типов: `green`, `red`, `yellow`, `blue`, `purple`, `deepgreen`, `pink`.

## Палитра

Значения мнемоник заданы один раз в `project/overrides/assets/config-light.css` на `html.theme-light`. Это те же имена и hex, что красят легаси-список: `--color-*` и `--color-bg-*` из `uikit.css` (его подключает `lu-original.css`), плюс `--pink` из блока variables в `lu-original.css`. Короткие `--blue`, `--green`, `--bgblue` из того же блока список не читает — у них другие hex. В разметке hex не пишется. Незнакомая мнемоника не красится. `--color-lgrey` ядра (рамки, `#d5d5d5`) не подменяем легаси `#b9bac7`.

Светлая тема и остальные токены кабинета: [ui-theme.md](ui-theme.md).

## Фильтры

У каждого столбца грида есть фильтр. Подпись фильтра совпадает с заголовком столбца.

Справочники (`Диагноз`, `Лаборатория`, `Анализ`, `Статус мутации`, `Статус HRD`, `Статус`) — мультивыбор. Даты создания — календарный диапазон. «Дата принятия материала» и «Дата выполнения» в базе ещё INT unix: диапазон дат переводится в timestamp суток (`compare: unix`). Дата рождения — колонка DATE. Текстовые поля (код, ФИО, пол, регионы, врач) — вхождение подстроки. «Дубль» — числовой диапазон: `0` нет, `1` повтор того же теста, `2` повтор в другой лаборатории.

Отдельно от столбцов ФИО и «Врач»:

| Фильтр | Что ищет |
|--------|----------|
| Фамилия пациента | только `t_pacient.varc_surname` |
| Фамилия врача | только `t_users.varc_surname` врача |

Фильтр столбца «ФИО пациента» по-прежнему ищет фамилию, имя и отчество вместе. Фильтр столбца «Врач» — полное ФИО врача.

## История логики

### 2026-10-11 — цвет статуса, бейдж типа, фильтры

- **Тип:** новая логика
- **Было:** грид без подсветки и без фильтров по столбцам
- **Стало:** фон строки и легенда по `t_analiz_status.varc_color`, бейдж типа по `t_analiztype.varc_color`, фильтр на каждый столбец плюс фамилия пациента и фамилия врача

### 2026-10-11 — легенда сплошной мнемоникой

- **Тип:** правка неверной логики
- **Было:** образец легенды заливали `--color-bg-*` (бледный фон строки), на серой плашке он читался как серый; бейдж красили inline `var(--color-*)`, для pink завели `--color-pink`
- **Стало:** образец и бейдж — класс `bg-{мнемоника}`. Сплошные цвета и фоны строк — из `uikit.css`, pink — `--pink` из `lu-original.css`
